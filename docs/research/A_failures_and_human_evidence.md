Retrieved 2026-11-11. Every URL below was fetched in this session. **Chk** column: `g` = the number/quote was re-checked by `curl` + `grep` against the raw page text; `p` = read directly from the PDF page images; `f` = taken from the WebFetch extraction of the page (fetched, but text passed through a summarizer; quotes are as returned). Failure classes: (a) fabricated results, (b) fabricated/wrong citations, (c) leakage / metric gaming / editing evaluation, (d) seed noise / missing statistics / selection bias, (e) weak novelty / plagiarism, (f) crashed or incomplete work reported as success, (g) reviewer-agent unreliability, (h) cost/time blow-ups, (i) other.

## Part 3. Design requirements the evidence supports

| ID | Requirement | Evidence |
|---|---|---|
| R1 | **Make evaluation code physically unreachable.** Enforce this in the sandbox, not the prompt: data splits, scorer and timer read-only or out of process, hash-checked each iteration, and any diff touching them auto-reverted. In autoresearch it is stated as an instruction ("Do not modify"); neither the README nor program.md describes enforcing it | F3, F15, F16 (read-only tests work, special-casing remains), F17, F19, F30, F31 (reads test labels) |
| R2 | **Lock a test split away from the loop.** Select on validation only; score the locked test once at the end; report the val-test gap | F14 (9-13 pt gap), F6, B1 (Private leaderboard) |
| R3 | **Keep/revert only above a measured noise floor.** Re-run the baseline across seeds to estimate σ; keep only if the gain beats it (or a paired multi-seed test passes); re-test before merging; final claims need ≥3 seeds with CI/SEM | F28, F29, F14 (high variance, 20 seeds), B2 (≥3 seeds, SEM), B16 (Karpathy averages 5 runs per leaderboard entry) |
| R4 | **Trace every number.** Each figure in the write-up must come from a logged run artifact via code (data-to-paper style), never typed by the writer agent; ban synthetic or placeholder data unless labelled | F5 (8/10), F8, F12 (20%), F1, F11 |
| R5 | **Let an external checker declare success or failure, not the agent.** Crashes, timeouts and invalid outputs count as failures and are reported (attempted / crashed / kept); the agent cannot self-declare "done" | F13, F19 (finished early), F20 (75% eval errors), F1 (42%), F8 (exit()), F31 (empty figure), B9 (0.5%) |
| R6 | **Resolve every citation** against DOI/arXiv/Semantic Scholar and check that it supports the claim; unresolvable references are removed | F22, F23, F24 (~56% of submissions flagged, derived as 100% minus the reported ~44%), F4, F2 |
| R7 | **Gate novelty and plagiarism with a human.** Run retrieval-based overlap search, then expert sign-off; automated plagiarism tools are not enough; describe results as tuning unless shown otherwise | F21 (24%), F2, B6, B13, B16 ("not novel ... (yet)") |
| R8 | **Never let an LLM reviewer be the acceptance gate.** Use several models calibrated against humans, scan for prompt injection, and report disagreement; a human makes the final call | F9 (6.1 vs 3.8), F10, F25 (r = 0.48, gap 2.73), F26, F18 (grader errors) |
| R9 | **Publish full traces with every result.** Ship logs, code and diffs per experiment so a third party can audit them; audits with logs catch far more | F7 (55% → 82% with logs), F15, F17, F5 (MLR-Judge used logs) |
| R10 | **Enforce budgets and a kill switch outside the agent.** Set per-run wall-clock limits and a global cost/time cap; no self-relaunch, no host shell, no payment credentials | F3, F8, F20 (cost limit), F17 (credit cards), F30 (10-min kill and "NEVER STOP" in program.md), F27 ("NEVER STOP LOOPING" in the Shopify blog author's prompt) |
| R11 | **Pre-declare the benchmark, metric and data subset.** Disclose any subsampling; forbid undisclosed metric switches | F7 (82.4% positional choice, undisclosed subsets), F6, F31 |
| R12 | **Make human comparisons fair and test transfer.** Match time and compute budgets and define the human baseline; check the gain at a larger scale or on a held-out task before claiming generality | B3 (2 h vs 32 h reversal), B4 (subset), B1/B2 (pass@k, mixed budgets), B16 (d12→d24 check), F27 ("somewhat overfit", single benchmark) |
