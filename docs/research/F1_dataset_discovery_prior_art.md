## Part 5: Verdict

**Already well served.**
- Keyword and metadata search inside platforms and aggregators: Google Dataset Search, DataCite (78M dataset DOIs), OpenAIRE, HF, Kaggle, and biomedical catalogues (NLM, NIAID, DataMed).
- Public APIs were confirmed for DataCite, OpenAIRE, re3data, HF, Kaggle, NLM Dataset Catalog and NIAID (DataMed **UNVERIFIED**; Google none described).
- MCP wrappers were found for HF, Kaggle, DataCite, Zenodo, OpenML and OpenAIRE. None was found for NLM, NIAID, DataMed or re3data.
- Multi-source search with a licence-metadata check already exists as MCP servers (data-aggregator-mcp, Mobus).
- Dataset–paper links exist (OpenAIRE ScholeXplorer).
- Retrieval ranking for research-idea queries is an established research topic (DataFinder, DataHunter, DSEBench, ACORDAR, NTCIR).

**Not found in the sources examined (candidate "unowned" space).** None of the tools or skills above does all of the following in one workflow:
1. Takes a researcher's natural-language question.
2. Verifies that every named dataset exists, by resolving its DOI or landing page and matching its identity.
3. Classifies the access tier from the repository's own statement, e.g. PhysioNet's "Open Access: Accessible by all users, with minimal restrictions on reuse", "Restricted Access … sign a Data Use Agreement", "Credentialed Access … complete the credentialing process" (https://physionet.org/about/database/).
4. Gives a criterion-based fit rationale.
5. Attaches resolvable prior-use papers.
6. Renders an interactive shortlist.

Also missing: no benchmark scores access-tier or licence correctness of recommendations, and the only health natural-language set (bioCADDIE) has 15 queries.

**Honest positioning statement (draft).** "dataset-scout is a verification-first agent skill, not a new search engine. It orchestrates existing indexes and APIs (DataCite, OpenAIRE, Hugging Face, Kaggle, domain catalogues). For every candidate it adds an existence check, an access/licence label taken from the source page, a fit rationale and prior-use evidence. The nearest prior art is data-aggregator-mcp and Mobus (multi-source search with licence checks), and DataFinder and DatasetResearch (recommendation benchmarks). We measure the gain over the same model with and without the skill."

**Name collision.** "DataScout" is already a UIST 2025 system and the name of several GitHub repos. Consider renaming before release.

**Evaluation recommendation.** Do not use an existing benchmark as the primary test. Each has a disqualifying problem:
- DataFinder: closed, frozen PwC corpus, ML only, gold limited to datasets from before the query.
- DatasetResearch: scores fine-tuning outcomes, not existence, access or licence.
- NTCIR, ACORDAR, DSEBench: government and RDF portals, keyword queries.
- bioCADDIE: 15 queries, and its download pages return 404.

Build a small pre-registered benchmark of about 30–60 questions, with a health and biomedical stratum, using gold that a third party can check:
1. **Questions** come from recent papers, ideally after the model's training cutoff, to limit contamination. Each paper's data-availability statement names the datasets it used, which gives "used" gold (DataFinder's principle with fresh papers).
2. **Access tier and licence gold** are copied verbatim from each dataset's landing page (PhysioNet levels, the HF `gated` flag, dbGaP-style controlled access) and archived with the date, for example in the Wayback Machine. Two annotators label them and an adjudicator resolves disagreements, with κ reported (bioCADDIE protocol). Platform fields are not trusted blindly, given the 70%+ / 50%+ licence-metadata error figures.
3. **Existence** is scored automatically. Each named dataset must resolve and match its identity. Use Rao et al.'s Wayback test to separate "never existed" from link rot.
4. **Fit** is graded 0/1/2 by annotators blind to which arm produced each result, on pooled outputs (the NTCIR/ACORDAR convention).
5. **Arms**: the same model run memory-only, with plain web search, and with the skill. "Without the skill" must state whether web search is on, because the headline changes with it: data-aggregator-mcp's memory-only arm reached recall 0.09, while web search reached 0.90 in the runs that finished. At least 3 runs per task, with time-outs reported separately. The decision rule is fixed in advance, following data-aggregator-mcp's design.
6. **Primary metrics**: hallucinated-dataset rate, access-tier accuracy, licence accuracy, precision@k of fit. Secondary metrics: recall against "used" gold, time and cost.

As secondary sanity checks only, report recall@k on a sample of DataFinder test queries and use DatasetResearch-pro demands as corner-case prompts, scoring existence and access rather than fine-tuning.
